## 1 目的与适用范围

本文档只约定 **前后端会"打架"的部分**：接口形态、字段命名与格式、错误码、状态枚举、链路标识、幂等、安全责任边界与兼容演进规则。

- **后端 Java 规范**见《编码规范（后端 Java）》；
- **前端 TypeScript / Vue 规范**见《编码规范（前端 TS/Vue）》；
- 两份规范引用本文档，且 **不得复制本文档内容**，避免口径漂移。

> 原则： **能被 `openapi.yaml` 描述的，一律以契约文件为准；契约文件描述不了的（错误响应细节、链路头、兼容策略），以本文档为准。**

## 3 接口形态与传输

| 项       | 约定                                                                                       |
|:---------|:-------------------------------------------------------------------------------------------|
| 风格     | RPC，`POST /api/v1/{module}/{action}`；不使用 RESTful 动词与路径参数                       |
| 请求体   | 业务参数**一律置于 `param`**；顶层可携带 `requestId`（UUID，缺省由服务端补全）             |
| 响应体   | `{code, message, data, requestId}`，HTTP 状态码恒为 200（业务错误由 `code` 表达）          |
| 内容类型 | `application/json; charset=utf-8`                                                          |
| 认证     | `Authorization: Bearer {token}`；`auth/login`、`auth/refreshToken`、`webhook/receive` 除外 |
| 分页     | 请求 `page`(≥1) / `size`(1~100，默认 20)；响应 `total` / `page` / `size` / `list`          |
| 文件下载 | `audit/export` 返回 CSV 流，前端使用 `responseType: 'blob'`（前端设计说明书 §9.5.2）       |

**唯一例外**：`POST /webhook/receive` 由 Git 平台回调，HTTP 状态码承载语义（200 / 400 / 401 / 503），见 `SRS` BR-W-09。

## 4 命名与数据格式

### 4.1 字段命名

| 场景     | 规则                                                                                | 示例                                                |
|:---------|:------------------------------------------------------------------------------------|:----------------------------------------------------|
| 传输字段 | `lowerCamelCase`，以 `openapi.yaml` 定义为准                                        | `taskId`、`filePath`、`hasTestCases`                |
| 数据库列 | `snake_case`（`LLD` §4）                                                            | `task_id`、`file_path`、`has_test_cases`            |
| 枚举值   | 大写 + 下划线                                                                       | `GENERATING_TEST`、`POSITIVE`、`DEPT_AND_SUB`       |
| 布尔字段 | 词根保持一致，**禁止同一语义出现两种形式**（不得同时存在 `default` 与 `isDefault`） | `isDefault`、`hasTestCases`、`fromCache`、`blocked` |

### 4.2 时间与数值

| 类型     | 格式                                                    | 说明                                       |
|:---------|:--------------------------------------------------------|:-------------------------------------------|
| 日期时间 | ISO-8601 **带时区偏移**，如 `2026-09-08T10:00:00+08:00` | 存储列为 `TIMESTAMPTZ`；前端按本地时区展示 |
| 日期     | `YYYY-MM-DD`                                            | 用于 `statDate`、时间范围 `start`/`end`    |
| 月份     | `YYYY-MM`                                               | 用于 `statMonth`                           |
| 金额     | 数值，单位「元」，2 位小数（`NUMERIC(12,2)`）           | `amount`、`amountLimit`                    |
| 单价     | 数值，**每千 Token** 单价                               | `inputPrice`、`outputPrice`                |
| Token 数 | 整数（`BIGINT`）                                        | `inputTokens`、`tokenLimit`                |
| 百分比   | 数值 `0~100`（不带 `%` 号）                             | `testCoverage`、`usedPercent`              |
| 置信度   | 数值 `0~1`                                              | `confidence`                               |

> 禁止使用时间戳（毫秒数）传输时间；禁止以字符串传输数值（金额、Token、百分比）。

### 4.3 空值与集合

- **集合字段永不返回 `null`**，无数据时返回 `[]`；
- 可选字符串字段缺省时 **省略该字段**或返回 `null` 均允许，前端一律按"空"处理并做兜底渲染；
- 分页查询无结果返回 `list: []` 且 `total: 0`，不使用 404 表达"无数据"；
- 前端禁止依赖字段顺序，禁止依赖未声明字段。

## 5 错误码与错误响应

### 5.1 错误码表

|  code   | 含义                | 前端处理                                         | 可否重试 |
|:-------:|:--------------------|:-------------------------------------------------|:--------:|
|   `0`   | 成功                | —                                                |    —     |
| `40001` | 参数校验失败        | `toast.error`，字段级错误按 §5.2 回填            |    否    |
| `40101` | 未登录 / Token 过期 | 清 token → 跳登录并带 `redirect`                 |    否    |
| `40301` | 无权限              | `toast.error('无操作权限')`                      |    否    |
| `40401` | 资源不存在          | `toast.warning` + 刷新列表                       |    否    |
| `50001` | 系统内部错误        | `toast.error(message, {description: requestId})` |    是    |
| `50002` | LLM 调用失败        | 提示"AI 服务调用失败"，Toast 提供重试按钮        |    是    |

前端统一处理见《前端详细设计说明书》§12。

### 5.2 字段级错误明细（本文档定义）

参数校验失败（`40001`）时，`data` 中 **可**携带 `detail` 对象，键为字段名、值为错误提示：

```json
{
  "code": 40001,
  "message": "参数校验失败",
  "data": {
    "detail": {
      "ruleCode": "规则编号已存在",
      "severity": "取值非法"
    }
  },
  "requestId": "uuid"
}
```

前端将 `detail` 按字段回填到 `FormField`（前端设计说明书 §12）。`detail` 为可选字段，后端未返回时前端仅展示 `message`。

### 5.3 重试语义

- 仅 `50001` / `50002` 提供用户可见重试；
- 写操作重试前必须先查幂等状态， **禁止盲目重放**（幂等键见 §7）；
- 前端网络异常提示中必须携带 `requestId` 便于排查。

## 6 状态与枚举字典

### 6.1 任务状态（唯一口径）

- 业务状态 `sub_status` 共 **14 个**：`RECEIVED`、`PARSING`、`QUEUED`、`ANALYZING`、`GENERATING_TEST`、`WRITING_BACK`、
  `RETRYING`、`TIMEOUT`、`COMPLETED`、`PARTIAL_SUCCESS`、`DEGRADED`、`FAILED`、`CANCELLED`、`SKIPPED_QUOTA`；
- 主状态 `status`：`0` 待处理 / `1` 处理中 / `2` 已完成 / `3` 失败 / `4` 已取消， **仅用于统计聚合**；
- **列表展示与筛选一律使用 `sub_status`（14 态）**（`SRS` §6.1 说明 1）；
- 前端字典映射见《前端详细设计说明书》§7.1，与 `openapi.yaml` 的 `SubStatus` 枚举严格一致。

### 6.2 其它枚举

`Dimension`、`Severity`、`Scenario`、`ConfirmStatus`、`VerifyStatus`、`CaseSource`、`FallbackMode`、`ChangeType`、
`PlatformType`、`ModelScene`、`NotifyChannel`、`TriggerCondition`、`QuotaStatusEnum`、`DataScope`、`ResourceType`、`RoleCode`、
`Granularity`、`PromptCategory` 均以 `openapi.yaml` 的 `components.schemas` 为准。

### 6.3 枚举扩展与前端兜底

- 新增枚举值属 **兼容变更**，服务端可先于前端发布；
- 前端遇到未识别枚举值： **展示原始值 + 次级样式（muted）**，禁止白屏、禁止抛错、禁止用 `unknown` 覆盖；
- 删除或重命名枚举值属 **破坏性变更**，按 §9 处理。

## 7 链路标识与幂等

### 7.1 标识定义

| 标识        | 生成方                           | 生命周期 | 用途                                                                 |
|:------------|:---------------------------------|:---------|:---------------------------------------------------------------------|
| `requestId` | 客户端（前端 `rpc()` 生成 UUID） | 单次请求 | 响应原样回传，用于问题排查与前端日志                                 |
| `traceId`   | 服务端（Webhook 入口生成）       | 全链路   | 贯穿 Webhook → Kafka → Worker → LLM 出站，落结构化日志（`LLD` §8.3） |

**传输方式（已同步至 `LLD` §8.3 与前端设计说明书 §6.2）**：

- `requestId` 置于 **请求/响应体**顶层；
- `traceId` 通过 HTTP 头 **`X-Trace-Id`** 透传；服务端日志与出站调用均输出该值；
- 前端请求拦截器生成 `requestId`，并在响应异常日志中一并输出 `requestId` 与 `traceId`。

### 7.2 幂等

| 场景                          | 幂等键                               | 有效期     |
|:------------------------------|:-------------------------------------|:-----------|
| Webhook 事件级（BR-W-07）     | `WEBHOOK_EVENT_ID:{eventId}`         | Redis 24h  |
| Webhook 业务级（BR-W-08）     | `{platformConfigId}_{repoId}_{mrId}` | 60 秒窗口  |
| Kafka 消息消费（`LLD` §10.4） | `aicr:mq:consumed:{msgId}`           | Redis 7 天 |
| 变更意图缓存（BR-05）         | `ANALYSIS_INTENT:{commitId}`         | Redis 24h  |

写操作（`create` / `apply` / `trigger` / `retry` / `confirmComment` / `rejectComment`）必须携带 `requestId`，服务端据此做重复提交拦截。

## 8 安全责任边界

| 事项             | 后端                                                                | 前端                                        |
|:-----------------|:--------------------------------------------------------------------|:--------------------------------------------|
| 敏感字段加密存储 | ✔ AES-256（`accessToken` / `apiKey` / `webhookSecret` / `secret`） | —                                           |
| 明文回显         | **禁止**；以 `hasAccessToken` 等布尔位代替                          | 表单留空表示不修改                          |
| 出网脱敏         | 送 LLM 前由 `SensitiveDataMasker` 扫描替换（`LLD` §7.3）            | —                                           |
| 日志脱敏         | 落盘前再脱敏（`LLD` §8.2 关键日志点 2）                             | 禁止打印/上报密钥与令牌                     |
| 数据权限         | **SQL 层按 `data_permission` 过滤**（`LLD` §7.2）                   | **禁止**拼 `deptId` / `authorId` 等范围参数 |
| 参数校验         | 必做（服务端为最终防线）                                            | 仅做交互优化，不可替代服务端校验            |
| XSS              | 输出转义                                                            | 除 Diff/代码渲染外禁用 `v-html`             |

## 9 兼容与演进

| 变更类型                 | 是否兼容   | 处理方式                                                                      |
|:-------------------------|:-----------|:------------------------------------------------------------------------------|
| 新增可选字段             | 兼容       | 直接发布；前端按 §4.3 兜底                                                    |
| 新增枚举值               | 兼容       | 服务端可先行；前端按 §6.3 兜底                                                |
| 新增接口 / action        | 兼容       | 直接发布                                                                      |
| 字段改名、删除、类型变更 | **破坏性** | 新增 action（如 `xxxV2`）并保留旧 action 至少一个内部版本，前端同步切换后下线 |
| 必填性由可选变必填       | **破坏性** | 同上，走灰度与版本化                                                          |
| 错误码语义变更           | **破坏性** | 需评审，同步修改本文档 §5 与前端 §12                                          |

**禁止**：在 `openapi.yaml` 已发布后直接修改字段语义而不升版本；禁止前端硬编码契约外字段。

## 10 前后端职责边界

| 事项                   | 归属                                                  |
|:-----------------------|:------------------------------------------------------|
| 数据范围过滤           | 后端（`data_permission` 表驱动）                      |
| 业务规则校验           | 后端（唯一权威）                                      |
| 状态文案与颜色映射     | 前端（字典 Store，`前端设计说明书` §7.1 / §7.2）      |
| 时间格式转换与时区展示 | 前端（服务端只出 ISO-8601）                           |
| 金额/百分比格式化      | 前端（服务端只出数值）                                |
| Diff 渲染与行号定位    | 前端（`diff2html` + `DiffView`，服务端出 `diffText`） |
| 导出文件名             | 前端（服务端只出流）                                  |
| 菜单与按钮权限         | 后端返回菜单树与权限码；前端仅做显隐控制              |

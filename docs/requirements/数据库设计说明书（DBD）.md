## 1 引言

### 1.1 编写目的

本文档为《AI 驱动代码评审与测试生成平台 v1.0》的 **数据库设计说明书（DBD）**，描述系统数据库的逻辑结构、物理表结构、约束（主键 /
唯一 / 外键 / CHECK）、索引、枚举字典、初始数据与迁移（Flyway）策略，为数据库开发、应用编码、DBA 运维、数据验收提供唯一事实依据。

### 1.2 适用范围

本文档适用于平台全部 9 个 Maven 模块（`aicr-web`、`aicr-webhook`、`aicr-worker`、`aicr-engine`、`aicr-service`、
`aicr-security`、`aicr-api`、`aicr-base`、`aicr-common`）及前端 `aicr-console` 的数据库访问设计，读者包括后端研发工程师、DBA、测试工程师与架构师。

> **范围约束**：本期（v1.0）为 **单租户**设计，所有表不引入 `tenant_id` 隔离；二期若支持多租户，将通过可空 `tenant_id` 列或
> Schema 隔离扩展，当前结构预留扩展点。

### 1.3 术语定义

| 术语           | 定义                                                                         |
|:---------------|:-----------------------------------------------------------------------------|
| Schema         | 数据库逻辑命名空间，本系统统一使用 `aicr`                                    |
| IDENTITY       | PostgreSQL 自增主键（`GENERATED BY DEFAULT AS IDENTITY`）                    |
| TIMESTAMPTZ    | PostgreSQL 带时区时间类型，内部统一 UTC 存储、应用层 `Asia/Shanghai` 展示    |
| JSONB          | PostgreSQL 二进制 JSON 类型，支持索引与高效查询                              |
| Flyway         | 数据库版本迁移工具，脚本存放于 `aicr-worker/src/main/resources/db/migration` |
| DDL / DML      | 数据定义语言 / 数据操作语言                                                  |
| dollar-quoting | PostgreSQL `$tag$...$tag$` 引用定界符，用于长文本（指令模板）免转义          |
| 逻辑删除       | 以 `deleted` 标志位软删除，数据物理保留                                      |
| 去规范化快照   | 将上游对象内容冗余存于本表（如 `prompt_template`），非外键引用               |

## 2 数据库总体设计

### 2.1 数据库选型与运行环境

| 项目         | 说明                                                                                    |
|:-------------|:----------------------------------------------------------------------------------------|
| DBMS         | PostgreSQL 18+                                                                          |
| Schema       | `aicr`（JDBC URL：`jdbc:postgresql://<host>:5432/postgres?schema=aicr`）                |
| 迁移管理     | Flyway Community；**仅 `aicr-worker` 启用迁移**，其余服务 `spring.flyway.enabled=false` |
| 迁移脚本目录 | `aicr-worker/src/main/resources/db/migration`                                           |
| 连接池       | HikariCP（`aicr-web` max=20，`aicr-webhook` max=10）                                    |
| 连接串凭据   | 通过环境变量注入，禁止硬编码；驱动 `org.postgresql.Driver`                              |
| 时区         | 库内统一 `TIMESTAMPTZ`（UTC 存储）；应用输出时区 `Asia/Shanghai`                        |

### 2.2 命名规范

| 对象      | 规范                                                                  | 示例                             |
|:----------|:----------------------------------------------------------------------|:---------------------------------|
| 表名      | 业务小写 snake_case，多词 `_` 连接                                    | `review_task`、`platform_config` |
| 主键      | 全部为 `id`（BIGINT identity）                                        | —                                |
| 索引      | `idx_{表名}_{列名}`（物理名全局唯一）                                 | `idx_review_task_status`         |
| 唯一约束  | `uk_{简短语义}` 或列级 `UNIQUE`                                       | `uk_task_repo_mr_commit`         |
| 外键约束  | `fk_{表缩写}_{被引用表}`                                              | `fk_task_repo`                   |
| 布尔/枚举 | 短枚举用 `SMALLINT + CHECK`；长枚举/需扩展用 `VARCHAR(32/64) + CHECK` | `status`、`dimension`            |
| 加密存储  | 敏感串用 `TEXT`，存 AES-256 Base64 密文                               | `access_token`、`api_key`        |

> 命名沿用 LLD §4 逻辑名（如 `IDX_TASK`）与物理名（`idx_review_task_task` 等）的对应关系——LLD 逻辑索引为便于阅读的别名，
> **物理索引名须全局唯一**。

### 2.3 通用字段与约束约定

所有 26 张表统一具备以下通用约定， **后续各表字段表不再重复罗列**：

| 通用列          | 类型                                                  | 说明                                   |
|:----------------|:------------------------------------------------------|:---------------------------------------|
| `id`            | `BIGINT GENERATED BY DEFAULT AS IDENTITY`             | 主键，全表统一                         |
| `created_at`    | `TIMESTAMPTZ NOT NULL DEFAULT NOW()`                  | 创建时间                               |
| `updated_at`    | `TIMESTAMPTZ NOT NULL DEFAULT NOW()`                  | 更新时间（例外见各表标注）             |
| 状态列 `status` | `SMALLINT NOT NULL DEFAULT 1 CHECK (status IN (0,1))` | 1-启用 / 0-停用（逐表语义见字典 §4.5） |

**时间戳例外表**：

| 表                                                                                         | 例外                                              |
|:-------------------------------------------------------------------------------------------|:--------------------------------------------------|
| `sys_dept`                                                                                 | 仅 `created_at`，无 `updated_at`                  |
| `audit_log`                                                                                | `updated_at` 可空、无默认值（终态日志，一般不改） |
| `false_positive_feature`                                                                   | 仅 `created_at`，无 `updated_at`                  |
| `sys_user_platform`、`data_permission`、`project` 等其余表均含 `created_at` + `updated_at` |                                                   |

其余约定：

- **逻辑删除**：仅 `sys_user.deleted`（0-未删 / 1-已删）使用，其余表状态删除走 `status=0`。
- **外键策略**：均在应用层保证业务完整性的前提下建库级外键（引用表为禁用 `ON DELETE CASCADE` 的安全对象）； **无触发器**。
- **自增种子**：显式插入 ID 后必须 `setval(pg_get_serial_sequence(...))` 重置序列（V1 末尾统一处理）。

### 2.4 表清单总览（共 26 张）

| # | 分类       | 表名                                                                                                                     |
|:--|:-----------|:-------------------------------------------------------------------------------------------------------------------------|
| 1 | 权限与组织 | `sys_dept`、`sys_user`、`sys_role`、`sys_user_role`、`sys_menu`、`sys_role_menu`、`data_permission`、`sys_user_platform` |
| 2 | 项目与仓库 | `project`、`repo`                                                                                                        |
| 3 | 评审核心   | `review_task`、`review_change_analysis`、`review_comment`、`test_case`                                                   |
| 4 | 规则与指令 | `prompt_template`、`prompt_version`、`review_rule`、`test_strategy`                                                      |
| 5 | 接入与配置 | `platform_config`、`model_config`、`notification_config`                                                                 |
| 6 | 反馈闭环   | `false_positive_feature`、`fix_sample`                                                                                   |
| 7 | 运维与成本 | `audit_log`、`cost_quota`、`cost_consumption`                                                                            |

### 2.5 核心实体关系（文字级 ER 摘要）

```
sys_dept 1─n sys_user  1─n project  1─n review_task(dept_id 冗余)
sys_user 1─n sys_user_role n─1 sys_role  1─n sys_role_menu n─1 sys_menu
data_permission(主体=ROLE/DEPT) —— 无外键，subject_id 按 subject_type 指向 sys_role/sys_dept
platform_config 1─n sys_user_platform(platform_username → 解析 sys_user)        [FR-022]
platform_config 1─n repo  1─n review_task   （repo 归属 project，成本主体 PROJECT）
project 1─n repo；repo 0/1─n review_task；repo.test_strategy_id → test_strategy（无 FK）
test_strategy 1─n review_task(test_strategy_id FK)；review_rule n─1 review_comment.rule_id（可空）
review_task 1─n review_change_analysis(1:1, task_id UNIQUE)
review_task 1─n review_comment 1─n false_positive_feature(可选)；review_comment 1─n fix_sample(可选)
review_task 1─n test_case
prompt_template 1─n prompt_version；model_config 1─n cost_consumption、1─n review_change_analysis
cost_quota / cost_consumption 主体：DEPT|PROJECT（subject_id 无外键，按 subject_type 指向 sys_dept/project）
audit_log：独立运维日志
```

外键完整清单见 §4.3。

## 3 物理表结构详细设计

> 各表字段表约定：仅列出 `id` 之外的特殊列与业务列，通用 `id / created_at / updated_at`（及默认 `status`）见 §2.3；如某表无
> `updated_at` 将单独注明。

### 3.1 权限与组织

#### 3.1.1 `sys_dept` 部门表（FR-016）

存放组织架构；树形父子关系由应用层维护（`parent_id=0` 为根， **无自引用外键**）。 **无 `updated_at`**。

| 字段       | 类型        | 允许空 | 默认 | 约束与说明        |
|:-----------|:------------|:-------|:-----|:------------------|
| dept_name  | VARCHAR(64) | NO     | -    | 部门名称          |
| parent_id  | BIGINT      | YES    | 0    | 父部门 ID，0 为根 |
| sort_order | INTEGER     | YES    | 0    | 排序序号          |
| leader     | VARCHAR(64) | YES    | -    | 部门负责人        |

#### 3.1.2 `sys_user` 用户表（FR-014）

| 字段     | 类型         | 允许空 | 默认 | 约束与说明                                                  |
|:---------|:-------------|:-------|:-----|:------------------------------------------------------------|
| username | VARCHAR(64)  | NO     | -    | 登录名，**UNIQUE**                                          |
| password | VARCHAR(256) | NO     | -    | BCrypt 哈希                                                 |
| email    | VARCHAR(128) | YES    | -    | 邮箱；FR-022 作者自动绑定的 email 匹配依据                  |
| phone    | VARCHAR(20)  | YES    | -    | 手机号                                                      |
| dept_id  | BIGINT       | YES    | -    | FK `fk_user_dept`→`sys_dept`；索引 `idx_sys_user_dept`      |
| status   | SMALLINT     | NO     | 1    | 1-启用 / 0-停用（兜底账号 `system_anonymous` 为 0，禁登录） |
| deleted  | SMALLINT     | NO     | 0    | 逻辑删除：0-未删除 / 1-已删除，`CHECK(deleted IN (0,1))`    |

#### 3.1.3 `sys_role` 角色表（FR-015）

| 字段        | 类型         | 允许空 | 默认 | 约束与说明                                    |
|:------------|:-------------|:-------|:-----|:----------------------------------------------|
| role_code   | VARCHAR(32)  | NO     | -    | 角色编码（ADMIN/PM/QA/DEVELOPER），**UNIQUE** |
| role_name   | VARCHAR(64)  | NO     | -    | 角色名称                                      |
| description | VARCHAR(256) | YES    | -    | 角色描述                                      |
| is_system   | SMALLINT     | NO     | 0    | 1-系统内置（禁删）/ 0-自定义，`CHECK`         |

#### 3.1.4 `sys_user_role` 用户角色关联表

多对多关联（唯一性由应用层保证，未建库级唯一约束）。

| 字段    | 类型   | 允许空 | 默认 | 约束与说明                                                |
|:--------|:-------|:-------|:-----|:----------------------------------------------------------|
| user_id | BIGINT | NO     | -    | FK `fk_ur_user`→`sys_user`；索引 `idx_sys_user_role_user` |
| role_id | BIGINT | NO     | -    | FK `fk_ur_role`→`sys_role`；索引 `idx_sys_user_role_role` |

#### 3.1.5 `sys_menu` 菜单表（FR-015）

| 字段            | 类型         | 允许空 | 默认 | 约束与说明                                              |
|:----------------|:-------------|:-------|:-----|:--------------------------------------------------------|
| parent_id       | BIGINT       | NO     | 0    | 父菜单 ID（0 为根）；索引 `idx_sys_menu_pid`            |
| menu_name       | VARCHAR(64)  | NO     | -    | 菜单名称                                                |
| menu_code       | VARCHAR(64)  | NO     | -    | 菜单标识，**UNIQUE**                                    |
| menu_type       | SMALLINT     | NO     | 2    | 1-目录 / 2-菜单 / 3-按钮，`CHECK(menu_type IN (1,2,3))` |
| path            | VARCHAR(256) | YES    | -    | 前端路由路径                                            |
| component       | VARCHAR(256) | YES    | -    | 前端组件路径                                            |
| icon            | VARCHAR(64)  | YES    | -    | 图标                                                    |
| permission_code | VARCHAR(64)  | YES    | -    | 权限标识（如 `review:list`、`review:confirmComment`）   |
| sort_order      | INTEGER      | YES    | 0    | 排序序号                                                |
| visible         | SMALLINT     | NO     | 1    | 1-可见 / 0-隐藏，`CHECK`                                |

#### 3.1.6 `sys_role_menu` 角色菜单关联表（FR-015）

| 字段    | 类型   | 允许空 | 默认 | 约束与说明                                                |
|:--------|:-------|:-------|:-----|:----------------------------------------------------------|
| role_id | BIGINT | NO     | -    | FK `fk_rm_role`→`sys_role`；索引 `idx_sys_role_menu_role` |
| menu_id | BIGINT | NO     | -    | FK `fk_rm_menu`→`sys_menu`；索引 `idx_sys_role_menu_menu` |

> 唯一约束：`uk_role_menu (role_id, menu_id)`。

#### 3.1.7 `data_permission` 数据权限表（FR-017）

主体（角色/部门）× 资源 × 范围 的数据权限矩阵（SRS §7.2 / LLD §7.2）。

| 字段          | 类型        | 允许空 | 默认 | 约束与说明                                                      |
|:--------------|:------------|:-------|:-----|:----------------------------------------------------------------|
| subject_type  | VARCHAR(16) | NO     | -    | 主体类型：`ROLE` / `DEPT`，`CHECK`                              |
| subject_id    | BIGINT      | NO     | -    | 主体 ID（按 subject_type 指向 `sys_role` / `sys_dept`，无外键） |
| resource_type | VARCHAR(32) | NO     | -    | 资源类型：`REVIEW_TASK` / `DASHBOARD` / `RULE`，`CHECK`         |
| scope         | VARCHAR(16) | NO     | -    | 范围：`ALL` / `DEPT_AND_SUB` / `SELF`，`CHECK`                  |

> 索引：`idx_data_permission_subject (subject_type, subject_id)`。

#### 3.1.8 `sys_user_platform` 用户平台账号绑定表（FR-022）

解决 Git 平台账号 ↔ 系统用户映射（Webhook 仅携带平台 username/email，须解析出 `review_task.author_id`）。

| 字段               | 类型         | 允许空 | 默认 | 约束与说明                                                                          |
|:-------------------|:-------------|:-------|:-----|:------------------------------------------------------------------------------------|
| user_id            | BIGINT       | NO     | -    | 系统用户 ID；FK `fk_up_user`→`sys_user`；索引 `idx_sys_user_platform_user`          |
| platform_config_id | BIGINT       | NO     | -    | 平台接入 ID；FK `fk_up_platform`→`platform_config`；索引 `idx_sys_user_platform_pf` |
| platform_user_id   | VARCHAR(64)  | YES    | -    | 平台侧用户 ID                                                                       |
| platform_username  | VARCHAR(128) | NO     | -    | 平台侧用户名                                                                        |
| platform_email     | VARCHAR(128) | YES    | -    | 平台侧邮箱                                                                          |

> 唯一约束：`uk_user_platform (platform_config_id, platform_username)`。
> 作者解析策略（LLD §4.26）：①用户名精确匹配 → ②email 匹配并自动写绑定 → ③兜底账号 `system_anonymous` 并写 WARN 审计。

| score              | INTEGER      | YES    | -     | 综合评分                                                                                                          |
| has_test_cases     | BOOLEAN      | YES    | FALSE | 是否包含测试用例                                                                                                  |

## 5 关键业务状态设计

### 5.1 评审任务状态（review_task）

**主状态 `status`**（单向不可逆：0 → 1 → 2/3/4，禁止 2/3/4 间互转、禁止回退 0）：

| 状态码 | 状态名称 | 说明                     |
|:-------|:---------|:-------------------------|
| 0      | 待处理   | 任务已接收，尚未开始处理 |
| 1      | 处理中   | 任务正在处理中           |
| 2      | 已完成   | 任务已成功完成           |
| 3      | 失败     | 任务处理失败             |
| 4      | 已取消   | 任务已被取消             |

**业务状态 `sub_status`**（VARCHAR 细粒度，与主状态映射见 LLD §6.3）：

`RECEIVED / PARSING / QUEUED / ANALYZING / GENERATING_TEST / WRITING_BACK / COMPLETED / PARTIAL_SUCCESS / FAILED / TIMEOUT / CANCELLED / RETRYING / DEGRADED / SKIPPED_QUOTA`

**受控回退**（仅 3 条，须记录审计并累加重试次数）：`TIMEOUT→RETRYING`、`PARTIAL_SUCCESS→WRITING_BACK`、`DEGRADED→ANALYZING`。

### 5.2 评审意见确认状态（review_comment.confirm_status）

| 值 | 含义   | 落库流向                                                                 |
|:---|:-------|:-------------------------------------------------------------------------|
| 0  | 待确认 | QA 待确认（初始态）                                                      |
| 1  | 有效   | 确认有效且已修复 → 沉淀 `fix_sample`（BR-FB-03）；确认有效但未修复不沉淀 |
| 2  | 误报   | 沉淀 `false_positive_feature`（BR-FB-01/02，负面约束注入源）             |

### 5.3 测试用例验证状态（test_case.verify_status）

| 值 | 含义   | 说明                            |
|:---|:-------|:--------------------------------|
| 0  | 待验证 | AI 生成后初始态                 |
| 1  | 已通过 | QA 验证通过                     |
| 2  | 已失败 | QA 验证失败（可回到待验证重测） |

## 7 数据库迁移管理（Flyway）

### 7.1 迁移策略

| 约定       | 说明                                                                                                                                                                                 |
|:-----------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 工具       | Flyway Community（SQL-based migration）                                                                                                                                              |
| 目录       | `aicr-worker/src/main/resources/db/migration`（仅该单元加载）                                                                                                                        |
| 执行者     | 仅 `aicr-worker` 启动时执行迁移（`spring.flyway.enabled=true`）；`aicr-web`/`aicr-webhook` 等一律 `enabled=false`（HLD §2.4.6）                                                      |
| 命名       | 基线 `V1__init.sql`；增量 `V{yyyyMMdd}_{两位序号}__{简述}.sql`（如 `V20260912_01__add_repo_is_secret.sql`），按版本号升序执行，写入 Flyway 历史表（与《开发分支管理规范》§6.1 一致） |
| 破坏性变更 | **禁止修改已发布的脚本**（会导致校验和失败）；一律新增更高版本脚本                                                                                                                   |
| 幂等       | 数据型迁移须 `WHERE NOT EXISTS` / `IF NOT EXISTS`；种子显式 ID 后须 `setval` 重置序列                                                                                                |
| 环境       | 开发种子（V1 明文占位 key）仅限本地；生产由管理端界面写入 AES-256 密文                                                                                                               |

### 7.2 迁移脚本清单

| 脚本           | 内容概要                                                                                                                                                                                             |
|:---------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `V1__init.sql` | 26 张表 DDL（建表 + 约束 + 索引 + 注释）与组织/权限/菜单/指令/规则/策略全部初始数据；含 `review_task.external_repo_id` 列、`PTM-REVIEW-COMMENT` 模板、模型与平台开发占位种子；末尾 `setval` 重置序列 |

### 7.3 对象注释规范

所有表均通过 `COMMENT ON TABLE / COMMENT ON COLUMN`（列注释主要存在于脚本与 LLD 字段说明中）维护可读语义；指令/规则类长文本使用
dollar-quoting `$pt$...$pt$`，禁止使用转义拼接。

## 8 数据安全设计

### 8.1 敏感字段加密存储

| 表                  | 加密列（AES-256，Base64 密文 TEXT）     | 说明         |
|:--------------------|:----------------------------------------|:-------------|
| platform_config     | `access_token`、`webhook_secret`        | Git 平台令牌 |
| model_config        | `api_key`                               | LLM 密钥     |
| notification_config | `webhook_url`（含 token）、`secret`     | 通知渠道凭证 |
| sys_user            | `password`（BCrypt 哈希，非对称可还原） | 登录口令     |

密钥管理：AES 主密钥存放于外部密钥服务 / 环境变量（LLD §7.4），支持轮换与旧密钥过渡期；
**业务代码、日志、迁移脚本不得出现真实密钥明文**。

### 8.2 入库文本脱敏

- 发送 LLM 前执行 `SensitiveDataMasker`（LLD §7.3）：API Key/Password/Secret/手机号/邮箱正则脱敏为 `***REDACTED***`。
- 反馈闭环入库样本已脱敏：`fix_sample.problem_code / fixed_code`、`false_positive_feature.code_snippet`、`review_rule` /
  指令正文中的示例均为非敏感形态。

### 8.3 数据权限隔离（读取层）

`review_task` 类查询按 `data_permission` 注入过滤（MyBatis Interceptor / AOP）：

- ADMIN：全量；PM/QA：`dept_id ∈ (本人部门及下级部门)`；DEVELOPER：`author_id = 本人`；
- 兜底账号产生的任务 `dept_id` 为空，仅 ADMIN 可见。

### 8.4 审计与保留

- 配置/权限/回退等敏感操作写入 `audit_log`（含操作人、类型、明细 JSONB、IP）； **默认保留 180 天**，超期由清理任务归档删除。

## 9 运维与高可用建议

### 9.1 备份与恢复

- 全量：`pg_dump`（custom 格式）每日低峰执行，保留 ≥ 7 天；增量建议开启 WAL 归档（PITR）；
- 恢复演练纳入版本发布流程；Flyway 历史表随库备份，保证迁移状态可重建。

### 9.2 连接池

- `aicr-web`（console 服务）Hikari 上限 20；`aicr-webhook` 上限 10；`aicr-worker` 依据消费者并发调整；
- 迁移执行期间如并发启动多实例，由 Flyway 内置锁保证唯一执行（建议仍保持单一 worker 实例策略）。

### 9.3 数据清理与归档

| 数据                          | 策略                                                       |
|:------------------------------|:-----------------------------------------------------------|
| audit_log                     | 默认保留 180 天（FR-013）                                  |
| review_task / comment / 关联  | 生产按容量评估启用冷归档（保留分析报表所需窗口）           |
| false_positive_feature        | 保留阈值后抽样清理（防无限增长，保留低频特征质量）         |
| cost_consumption              | 日粒度永久保留（成本看板审计依据），超期压缩到月表（二期） |
| notification/其他队列类 JSONB | 随配置删除                                                 |

### 9.4 时钟与时区

- 库统一 `TIMESTAMPTZ`（UTC 存储），应用输出 `Asia/Shanghai`（`spring.jackson.time-zone`）；禁止应用层拼接本地时间字符串入库。

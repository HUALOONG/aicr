## 1 引言

### 1.1 编写目的

SRS 与 LLD 定义了 6 大主菜单、21 个子菜单的功能与接口，但未定义前端工程结构、组件划分、交互与性能方案。本文档填补该空白，作为前端编码、UI 走查与联调的唯一依据。

### 1.2 适用范围

覆盖管理控制台全部页面与组件。适用于前端研发、UI 设计、测试与联调人员。

### 1.3 术语定义

| 术语      | 定义                                                             |
|:----------|:-----------------------------------------------------------------|
| RPC 接口  | 统一 `POST /api/v1/{module}/{action}` 风格（SRS §5.1）           |
| 动态路由  | 由后端返回的菜单树在运行时生成的前端路由                         |
| 数据权限  | 控制"能看到哪些数据"，与菜单权限独立（SRS FR-017）               |
| Diff 视图 | 展示代码变更差异并支持行级评审意见标注的组件（FR-006 Tab2 核心） |

**技术栈：Vue 3 + TypeScript + Vite+ + Tailwind CSS v4 + shadcn-vue(Reka UI)。**

其中 Vite+（`vp` CLI）统一了开发/构建/测试/规范四条链路，Tailwind CSS v4 是唯一的样式与设计语言来源。

### 2.2 UI 组件层

UI 组件层采用 **shadcn-vue + Reka UI**，以 Tailwind 原子类与 CSS 变量为样式体系，主题 token 直接映射到 Tailwind v4 的 `@theme`。

**选型依据**：

1. **单一设计语言**：Tailwind v4 的 `@theme` 是唯一 token 来源，不额外维护 Less 变量与主题包；
2. **体积可控**：组件以源码形式位于 `src/components/ui/`，仅被引用者进入打包，无全量样式表；
3. **深度定制**：FR-006 的 Diff 视图、FR-007 的图谱面板等强定制场景不受组件库内部结构限制；
4. **无障碍**：Reka UI 提供焦点管理、键盘导航与 ARIA 属性，满足 §12 交互一致性要求。

**组件使用对照**（本文档后续统一使用右列方案）：

| 组件能力                              | 采用方案                                                           |
|:--------------------------------------|:-------------------------------------------------------------------|
| 数据表格                              | `Table` 原子组件 + `@tanstack/vue-table`（封装为 `DataTable`）     |
| 表单 / 表单项                         | `Form` / `FormField` + vee-validate + zod                          |
| 文本输入 / 多行输入                   | `Input` / `Textarea`                                               |

### 2.3 Diff 视图

FR-006 Tab2 采用 **diff2html + 自定义注入** 实现只读 Diff 渲染。

**选型依据**：本场景是只读查看（评审意见展示），不需要编辑、折叠、搜索等 IDE 能力；diff2html 直接产出带行号锚点的 DOM，行级标注与双向跳转实现成本最低，且体积对首屏 ≤2s 友好。

**数据来源**：Diff 原始文本不由前端生成，后端在 `review/getReport` 响应中一并返回（unified diff 格式），前端仅做渲染与交互。

> **与 Tailwind v4 的集成注意**：diff2html 自带 CSS 与 Tailwind preflight 存在冲突（preflight 会重置 `table`/`td` 边框与字号）。
> 处理方式见 §2.4.5。

### 2.4 Tailwind CSS v4 落地约定

#### 2.4.1 接入方式

Tailwind v4 **不需要** `tailwind.config.js` 与 `postcss.config.js`，全部配置在 CSS 内完成（CSS-first）：

```bash
pnpm add tailwindcss @tailwindcss/vite
```

```ts
// vite.config.ts（Vite+ 统一配置文件）
import {defineConfig} from 'vite'
import vue from '@vitejs/plugin-vue'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
    plugins: [vue(), tailwindcss()],
    resolve: {alias: {'@': fileURLToPath(new URL('./src', import.meta.url))}},
})
```

```css
/* src/styles/main.css —— 全站唯一样式入口 */
@import "tailwindcss";
@import "tw-animate-css";

/* 暗色模式：以 <html class="dark"> 切换（shadcn 约定） */
@custom-variant dark (&:is(.dark *));

/* 语义色：SRS 状态色 → Tailwind token */
@theme inline {
    --color-primary: var(--primary);
    --color-primary-foreground: var(--primary-foreground);
    --color-success: var(--success);
    --color-warning: var(--warning);
    --color-danger: var(--danger);
    --color-info: var(--info);
    --color-muted: var(--muted);
    --color-muted-foreground: var(--muted-foreground);
    --radius-card: var(--radius);
}

:root {
    --primary: oklch(0.58 0.20 259);      /* #1677ff */
    --success: oklch(0.65 0.16 150);      /* #52c41a */
    --warning: oklch(0.75 0.16 70);       /* #faad14 */
    --danger: oklch(0.60 0.22 25);        /* #ff4d4f */
    --info: oklch(0.62 0.19 240);
    --radius: 0.375rem;                   /* 6px */
}

.dark {
    /* 暗色下仅覆盖变量，组件类名不变 */
    --primary: oklch(0.68 0.18 259);
}
```

#### 2.4.2 关键约定

| 约定                    | 说明                                                                                      |
|:------------------------|:------------------------------------------------------------------------------------------|
| 无 `tailwind.config.js` | 主题、断点、动画统一写在 `main.css` 的 `@theme` 中                                        |
| 自动内容检测            | v4 自动扫描项目源文件；被忽略的目录用 `@source` 显式声明                                  |
| 动态类名白名单          | 字典色等拼接类名必须用 `@source inline("...")` 生成，禁止拼接用户输入（防样式注入）       |
| 语义色优先              | 业务色一律用 `--color-success/warning/danger/info`，不直接写 `text-red-500`（便于换主题） |
| 暗色实现                | 以 CSS 变量 + `.dark` 类为主，`dark:` 变体仅在变量无法覆盖时使用                          |
| 组件变体                | 一律用 `cva()` 管理，禁止在模板中散落条件类名                                             |

```css
/* 例：状态/等级色的动态类名白名单（对应 §7.1/§7.2） */
@source inline("bg-{muted,success,warning,danger,info}/{10,15}");
@source inline("text-{muted-foreground,success,warning,danger,info}");
@source inline("border-{muted,success,warning,danger,info}/{20,30}");
```

#### 2.4.3 样式组织

```
src/styles/
├── main.css        # @import tailwindcss + @theme + 语义色变量（唯一入口）
└── diff2html.css   # diff2html 主题适配 + preflight 冲突修复（§2.4.5）
```

#### 2.4.4 组件层目录（shadcn-vue CLI）

组件源码由 `npx shadcn-vue@latest add <component>` 生成到 `src/components/ui/`，配置落在 `components.json`（别名 `@/components`、`@/lib/utils`）。
**规则**：生成后纳入版本管理，可在业务中修改；升级时以 diff 方式合并，不整体覆盖。

#### 2.4.5 与 diff2html 样式共存

```css
/* src/styles/diff2html.css —— 必须在 main.css 之后导入 */
@import "diff2html/bundles/css/diff2html.min.css";

@layer base {
    /* 修复 Tailwind preflight 对 d2h 表格的边框/字号重置 */
    .d2h-diff-table td,

    .d2h-code-line-ctn {font-size: 12.5px; line-height: 1.6;}

}

/* 行级评审标记：按严重等级着色（对应 §9.3.2） */
.d2h-code-line .comment-marker { /* ... */ }
.d2h-code-line .comment-marker[data-severity="BLOCKER"] {background: var(--danger);}
.d2h-code-line .comment-marker[data-severity="CRITICAL"] {background: var(--warning);}
```

## 4 路由与菜单

### 4.1 菜单数据来源

登录后调用 `auth/getCurrentUser`，从 `data.menus` 取菜单树（`sys_menu` 表，见 LLD §4.24）。前端 **不硬编码菜单**，避免改权限要发版。

## 6 接口层设计

### 6.1 RPC 统一封装

所有接口均为 `POST /api/v1/{module}/{action}`，业务参数置于 `param`：

```ts
// api/rpc.ts
export async function rpc<TReq, TRes>(
    module: string, action: string, param?: TReq
): Promise<TRes> {
    const {data} = await http.post(`/api/v1/${module}/${action}`, {
        requestId: crypto.randomUUID(),
        param: param ?? {},
    })
    if (data.code !== 0) throw new BizError(data.code, data.message)
    return data.data
}
```

### 6.2 拦截器职责

| 拦截器 | 职责                                                                                                                   |
|:-------|:-----------------------------------------------------------------------------------------------------------------------|
| 请求   | 注入 `Authorization: Bearer {token}` 与 **`X-Trace-Id`** 头；生成 `requestId`（UUID）置于请求体顶层（与 `param` 同级） |
| 响应   | `code!==0` 统一 `toast.error`（vue-sonner）；`40101` 清 token 跳登录；`40301` 提示无权限                               |
| 异常   | 网络错误/5xx 提示"服务异常"，输出 `requestId` 便于排查                                                                 |

> 全局 Toast 由 `<Toaster />` 挂载在 `App.vue`，不使用命令式 `message`。

### 6.3 模块封装示例

```ts
// api/modules/review.ts
export const reviewApi = {
    list: (p: ReviewListParam) => rpc<ReviewListParam, ReviewListData>('review', 'list', p),
    getReport: (p: TaskIdParam) => rpc<TaskIdParam, ReportData>('review', 'getReport', p),
    confirm: (p: ConfirmCommentParam) => rpc('review', 'confirmComment', p),
    trigger: (p: ReviewTriggerParam) => rpc<ReviewTriggerParam, TaskBrief>('review', 'trigger', p),
}
```

> TS 类型由 `openapi.yaml` 通过 `openapi-generator`（`-g typescript-axios`）或 `openapi-typescript` 生成到 `api/types/`，
> **标记为只读、禁止手改**。

- 访问映射统一经 `getStatusMeta(key)` 封装，内部 `?? fallback`，不在组件内直接索引原始对象。

```ts
// components/DiffView/index.vue 关键流程

/** 1. 入参契约 */
interface ReviewCommentItem {
    id: number
    filePath: string
    lineNo: number
    severity: 'BLOCKER' | 'CRITICAL' | 'MINOR'   // 决定标记颜色（§2.4.5）
}

interface DiffViewProps {
    diffText: string               // unified diff
    comments: ReviewCommentItem[]  // 待标注的评审意见
    outputFormat?: OutputFormat    // 默认 'line-by-line'
}

/** 2. outputFormat 仅两种取值 */
type OutputFormat = 'side-by-side' | 'line-by-line'

/** diff2html 渲染器契约（实例由 diff2html 提供） */
interface Diff2HtmlUI {
    draw(diffText: string, config: Diff2HtmlConfig): void
}

interface Diff2HtmlConfig {
    drawFileList: boolean
    matching: 'lines' | 'words'
    outputFormat: OutputFormat
}

/**
 * 3~5. 渲染 diff → 按行匹配评论 → 插入标记 → 事件委托
 */
function renderWithComments(
    root: HTMLElement,
    ui: Diff2HtmlUI,
    props: DiffViewProps,
    onSelect: (commentId: number) => void,
): void {
    ui.draw(props.diffText, {
        drawFileList: true,
        matching: 'lines',
        outputFormat: props.outputFormat ?? 'line-by-line',
    })

    // 3. 遍历渲染结果：按 [data-line-num] 与文件名匹配 comments
    const lines = root.querySelectorAll<HTMLElement>('[data-line-num]')
    for (let i = 0; i < lines.length; i++) {
        const line = lines[i]
        const file = line.closest<HTMLElement>('[data-file]')?.dataset.file
        const lineNo = Number(line.dataset.lineNum)
        const hit = props.comments.filter((c) => c.filePath === file && c.lineNo === lineNo)[0]
        if (!hit) continue

        // 4. 命中行插入评论标记 <span class="comment-marker" data-comment-id>
        const marker = document.createElement('span')
        marker.className = 'comment-marker'
        marker.dataset.commentId = String(hit.id)
        marker.dataset.severity = hit.severity
        line.appendChild(marker)
    }

    // 5. 事件委托：点击 marker → 抛出选中事件
    root.addEventListener('click', (e) => {
        const marker = (e.target as HTMLElement).closest<HTMLElement>('.comment-marker')
        if (marker?.dataset.commentId) onSelect(Number(marker.dataset.commentId))
    })
}

/** 6. 暴露给父组件：滚动到指定文件的指定行 */
function scrollToLine(file: string, lineNo: number): void {
    const target = document.querySelector<HTMLElement>(
        `[data-file="${file}"] [data-line-num="${lineNo}"]`,
    )
    target?.scrollIntoView({behavior: 'smooth', block: 'center'})
}
```

> 全局 CSP；不得对用户输入使用 `v-html`。

**接口**：`review/getReport`（一次拉全三个 Tab 数据；**评论或用例超过 200 条时**改用 `review/getChangeAnalysis`、`review/getReviewComments`、

`review/updateTestCaseStatus`

## 10 关键组件设计

### 10.1 DiffView（★ 核心组件）

| 项     | 设计                                                                     |
|:-------|:-------------------------------------------------------------------------|
| Props  | `diffText: string`、`comments: ReviewCommentItem[]`、`activeId?: number` |
| Emits  | `select(commentId)`                                                      |
| Expose | `scrollToLine(filePath, lineNo)`                                         |
| 渲染   | diff2html `line-by-line` 模式；文件头可折叠，默认展开前 5 个文件         |
| 标注   | 按 `file_path + line_no` 匹配，行尾注入等级色标记 + 数量角标             |
| 性能   | 单文件 >1000 行时虚拟渲染（仅渲染可视区 + 前后缓冲），或提示"文件过大"   |
| 空态   | 无 diff 时展示"本次变更未获取到代码差异"                                 |

### 10.2 StatusTag

接收 `SubStatus`，从 `dict` Store 取 `{label, class, processing}`，输出 `<Badge :class="cn(meta.class)">`；
`processing` 态附带 lucide `Loader2`（`animate-spin`）图标。

### 10.3 ChartCard

统一图表容器（`Card`），封装三种状态：`loading`（`Skeleton`）、`empty`（`Empty`）、`error`（重试 `Button`）。
图表组件 `v-if="!loading && !empty"` 懒挂载，避免 ECharts 容器未尺寸化。

### 10.4 PermissionButton

包裹 shadcn-vue `Button`，内部检查 `user.permissions`，无权限则不渲染；`ghost` 模式下渲染为禁用态（`disabled`）并
用 `Tooltip` 提示。变体通过 CVA 与 `Button` 保持一致。

### 10.5 TraceGraph

G6 封装：props 接收 `nodes/edges`，内部处理布局、缩放、类型过滤；销毁时 `graph.destroy()` 防内存泄漏。

## 11 性能设计（首屏 ≤2s，SRS §4.1）

| 手段              | 落地方式                                                                        |
|:------------------|:--------------------------------------------------------------------------------|
| 路由懒加载        | 全部页面 `() => import()`（§4.2）                                               |
| 工具链            | `vp build`（Rolldown）替代 esbuild/Rollup 组合，构建与 HMR 更快                 |
| 组件按需          | shadcn-vue 组件以源码入库，仅被引用者进入打包；**无全量组件库样式**             |
| Tailwind CSS 体积 | v4 自动内容检测，仅生成使用到的类；动态类名用 `@source inline()` 收敛（§2.4.2） |
| ECharts 按需      | 仅引入 `PieChart/BarChart/LineChart` 与必要组件，约 300KB → 100KB               |
| Diff 库轻量       | 选用 diff2html 而非 Monaco（§2.3），省下约 2MB                                  |
| G6 懒加载         | 仅在进入变更追溯页时动态 `import('@antv/g6')`                                   |
| 大列表虚拟滚动    | `DataTable` 单页 >100 行启用 `@tanstack/vue-virtual`                            |
| 资源压缩          | `vp build` 产物开启 gzip + brotli，Nginx 侧开启                                 |
| 图标              | `lucide-vue-next` 具名导入，由 Rolldown tree-shaking，禁止 `import * as Icons`  |
| 依赖预构建        | `optimizeDeps` 预构建 ECharts/G6 等大依赖，减少首屏请求数                       |
| 缓存              | 静态资源 `Cache-Control: max-age=31536000, immutable`（hash 文件名）            |
| 避免首屏请求瀑布  | 登录态与菜单在守卫中一次拉取，页面内接口并行发起                                |
| 首屏防闪白        | 主题在 `main.ts` 同步写入 `<html class="dark">`，避免主题切换闪烁               |

**验收口径**：Chrome DevTools Performance，`DOMContentLoaded` ≤1s、首屏可交互 ≤2s（本地 Nginx + `vp build` 产物）；
另需满足 `vp build` 产出 CSS（gzip 后）≤ 30KB、首屏 JS（gzip 后）≤ 350KB。

## 12 错误处理与全局交互

| 场景             | 处理                                                                                                    |
|:-----------------|:--------------------------------------------------------------------------------------------------------|
| `40001` 参数错误 | `toast.error(message)`；表单字段级错误由后端 `data.detail` 回填到 `FormField`（结构见《编码规范》§5.2） |
| `40101` 未登录   | 清 token → 跳登录并携带 `redirect` 参数                                                                 |
| `40301` 无权限   | `toast.error('无操作权限')`                                                                             |
| `40401` 不存在   | `toast.warning` + 列表页刷新                                                                            |
| `50001` 系统错误 | `toast.error(message, {description: requestId})` 便于定位                                               |
| `50002` LLM 失败 | 提示"AI 服务调用失败，可稍后重试"，`toast` 提供 `action` 重试按钮                                       |
| 网络/超时        | `toast.error('网络异常，请检查网络后重试')`                                                             |

**全局交互约定**：

- 表格查询统一走 `DataTable` 的 `loading`（骨架行），不使用全屏 loading
- 删除等破坏性操作统一 `AlertDialog` 二次确认
- 写操作成功后 `toast.success` 并刷新列表
- 长文本超过 2 行省略（`line-clamp-2`）+ `Tooltip` 完整展示
- 所有 Toast 由 `App.vue` 中唯一的 `<Toaster rich-colors />` 渲染，禁止局部重复挂载

## 13 安全设计

| 项         | 措施                                                                                      |
|:-----------|:------------------------------------------------------------------------------------------|
| XSS        | 除 Diff/代码渲染外禁用 `v-html`；diff2html 输出依赖其内置转义；CSP `script-src 'self'`    |
| 样式注入   | 禁止用用户输入拼接 Tailwind 类名；动态类名一律走白名单映射 + `@source inline()`（§2.4.2） |
| Token 存储 | `localStorage`（便于多标签共享）；登出与 401 时清除                                       |
| 敏感数据   | 密钥类字段前端不缓存、不写日志；表单留空表示不修改                                        |
| 传输       | 全站 HTTPS；Dev 环境 Vite+ proxy 转发                                                     |
| 越权       | 数据权限由后端保证；前端不拼接数据范围参数                                                |
| 依赖安全   | CI 中执行 `vp install --frozen-lockfile` + `pnpm audit`；依赖锁定（pnpm-lock.yaml）       |

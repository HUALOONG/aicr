## 1 测试目标与范围

本计划定义从单元到生产验收的测试策略，确保达成 `SRS` §4 的非功能性指标与 26 个 FR 的可验证性。

**覆盖目标**：

- 后端整体单元测试覆盖率 **≥ 80%**（`SRS` §4.4）；`engine` 渲染/裁剪/状态机、`service` 权限过滤、Kafka 幂等为 **必测**；
- 前端核心组件（StatusTag / PermissionButton / ChartCard / DataTable）、工具函数（`getStatusMeta` 兜底、状态映射）、`rpc()`
  异常路径为 **必测**；
- LLM 调用、真实代码平台出站调用 **禁止**进入单测与集成测试，一律 Mock。

**不在范围**：探索性测试、UI 视觉走查（由设计走查替代）、压力测试中的极限容量（限 §4 性能基线）。

## 2 测试分层策略

| 层            | 工具                                                            | 目标                                   | 执行时机                   |
|:--------------|:----------------------------------------------------------------|:---------------------------------------|:---------------------------|
| 后端单元      | JUnit 5 + Mockito + AssertJ                                     | 方法级逻辑、分支覆盖                   | PR / `mvn verify`          |
| 后端架构测试  | ArchUnit                                                        | 依赖红线（HLD §2.4.3 / LLD 附录 C）    | PR / `mvn verify`          |
| 后端集成      | Spring Boot Test + Testcontainers（PostgreSQL / Redis / Kafka） | 跨模块、数据权限、Kafka 幂等、事务边界 | 合入 develop 后 / 每日构建 |
| 前端单元/组件 | Vitest + Vue Test Utils                                         | 组件行为、工具函数                     | PR / `vp test`             |
| 前端类型      | tsgo（`vp check`）                                              | 类型一致性（含 openapi 生成类型）      | PR                         |
| 契约测试      | 自研注解 + openapi 校验                                         | 实现与 `openapi.yaml` 字段一致         | PR                         |
| 接口/E2E      | Playwright                                                      | 主流程（登录→列表→报告→确认）          | 预发布环境                 |
| 性能          | k6 / JMeter                                                     | §4 性能基线                            | 版本发布前                 |
| 安全          | `dependency-check` + `pnpm audit` + 脱敏/签名校验               | §4.2 安全需求                          | 每日 / 发布前              |

## 3 测试环境

| 环境    | 用途                  | 数据                                                     |
|:--------|:----------------------|:---------------------------------------------------------|
| dev     | 本地开发自测          | 本地容器或 Testcontainers                                |
| test    | PR 集成测试、每日构建 | Testcontainers 临时实例，随跑随销                        |
| staging | E2E、性能、安全扫描   | 类生产数据（**脱敏**），Flyway 由 `aicr-worker` 自动迁移 |
| prod    | 仅监控与回归巡检      | 生产数据，不跑破坏性测试                                 |

- 三个中间件（PostgreSQL 18+ / Redis 8.0+ / Kafka 4.3+）以 Testcontainers 或环境提供，连接信息走配置注入（`SRS` §4.4）；
- 数据库迁移 **只由 `aicr-worker` 执行**（HLD §2.4.6），测试库同样经 worker 迁移后再跑集成测试。

## 4 单元测试

### 4.1 后端

- 命名 `XxxServiceTest` / `XxxRepositoryTest`，方法 `@DisplayName` 中文描述"给定-当-那么"；
- Mock 边界：`engine`、`service` 调用 LLM / 平台出站处必须 Mock，断言其 **入参脱敏后**内容（验证 `SensitiveDataMasker`
  生效，LLD §7.3）；
- **ArchUnit 测试必写**：`engine↛service`、`web↛engine`、`webhook↛{service,engine}`、`common↛Spring`；红线变更同步更新测试；
- 状态机：覆盖 LLD §6.2 的 **24 条流转**（含终态重入保护、降级/熔断路径）；
- 数据权限：`service` 层断言 SQL 注入了 `data_permission` 过滤（不靠 UI 校验）。

### 4.2 前端

- 工具函数：`getStatusMeta` 未知枚举兜底、`cn()` 合并、`SUB_STATUS_MAP` 映射；
- 组件：StatusTag / PermissionButton / ChartCard 的三种状态（正常/加载/空）、`DataTable` 分页与空态；
- **禁止**样式快照测试（Tailwind 类名易变），改行为断言；
- E2E 脚本覆盖：登录 → 任务列表（14 态筛选）→ 打开报告（Diff 视图）→ 确认意见；权限按钮可见性。

## 5 集成与契约测试

- **Kafka 幂等**：构造重复 `msgId` 消息，断言消费端丢弃且只落一次；业务去重键（`BR-W-08`）重复消息断言旧任务取消 +
  新任务创建在同一事务；
- **Webhook 接收**：模拟 GitLab / GitHub / Gitea 三类事件（见 §8 矩阵），断言签名校验、事件过滤、幂等去重、入队结果；
- **契约一致性**：在 `web` / `webhook` 启动期用注解校验 Controller 入参/出参与 `openapi.yaml` 对齐；契约变更未同步实现则
  PR 失败（开发分支管理规范 §6.2）。

## 6 性能测试

基线（`SRS` §4）：

| 指标             | 目标                                 | 工具            | 场景                      |
|:-----------------|:-------------------------------------|:----------------|:--------------------------|
| API 平均响应     | ≤ 2s                                 | k6              | 任务列表/报告查询混合负载 |
| Webhook P99      | ≤ 200ms                              | k6              | 并发事件入站（去重+入队） |
| 评审任务并发处理 | ≥ 50 QPS                             | k6              | 连续触发评审              |
| LLM 调用成功率   | ≥ 99.5%                              | 监控统计        | 长周期压测                |
| 前端首屏         | ≤ 2s                                 | Chrome DevTools | 本地 `vp build` 产物      |
| 资源体积         | CSS gzip ≤30KB / 首屏 JS gzip ≤350KB | `vp build` 产物 | 构建产物检查              |

性能测试 **禁止**触发真实 LLM（用 Mock 端点模拟延迟与失败，验证降级/熔断路径）。

## 7 安全测试

| 项       | 方法                                                                |
|:---------|:--------------------------------------------------------------------|
| 依赖漏洞 | `mvn dependency-check` + `pnpm audit`，阻断高危 CVE                 |
| 脱敏     | 单测断言送 LLM 前敏感字段被替换；集成测试断言落库密文               |
| 签名校验 | Webhook 用例覆盖合法/篡改/过期签名（BR-W-03/04/05/06）              |
| XSS      | 前端禁用 `v-html`（仅 Diff 渲染放行）；Diff 输出依赖 diff2html 转义 |
| 越权     | 接口层断言无 `deptId`/`authorId` 越权拼接；数据权限由后端保证       |
| 密钥     | 断言 `accessToken`/`apiKey`/`secret` 出网前为掩码，日志不落明文字段 |

## 8 重点场景清单（必测）

| 域       | 场景                                           | 验证点                                    |
|:---------|:-----------------------------------------------|:------------------------------------------|
| 状态机   | 24 条流转 + 终态重入                           | 状态正确推进、终态不可再流转              |
| Webhook  | 9 种事件（3 平台 × create/update/merge+close） | 签名、过滤、去重、入队                    |
| 幂等     | 事件级 24h + 业务级 60s + Kafka 7 天           | 重复消息单次生效                          |
| 降级     | LLM 超时/不可用                                | 置 `RETRYING`/`DEGRADED`，返回降级说明    |
| 大变更   | 超 1000 行/5 文件/20 文件                      | 阶段一分桶、阶段二串行、阶段三分批        |
| 配额     | NORMAL/WARN/CRITICAL/BLOCKED 四档              | 80%/90%/100% 阈值告警与熔断（BR-COST-03） |
| 数据权限 | 角色 × 范围组合                                | SQL 注入 `data_permission` 过滤正确       |
| 确认闭环 | 反馈 1/2 + 复盘标注                            | 进入特征库/样本库，驱动下一轮 Prompt 评估 |

## 9 测试数据管理

- 种子数据：9 条 `prompt_template`（LLD §3.3 / Prompt 设计说明书 §4）经 Flyway `V1__init.sql` 或 `V2__seed` 注入；
- 脱敏：测试数据中的姓名/手机号/邮箱使用生成器，禁止生产真实隐私数据入库；
- 外部依赖（LLM、代码平台）一律 Mock，提供可重放的响应录放（record/replay）以保证用例稳定。

## 10 入口/出口准则（DoD）

**进入测试前**：代码已合 `develop`、CI 全绿（含 ArchUnit、单测、前端 `vp check`/`vp test`）、契约校验通过。

**出口（可发布）**：

1. 后端覆盖率 ≥ 80% 且无关键路径未覆盖；
2. 全部必测场景（§8）通过；
3. 性能基线（§6）达标；
4. 安全扫描无高危漏洞；
5. 严重/致命缺陷清零，一般缺陷有规避方案并经产品确认。

**缺陷分级**：致命（阻断主流程/数据错乱）/ 严重（功能缺失）/ 一般（体验）/ 建议；致命与严重 **不允许**带入 `release/*`。

---

## 11 工具与 CI 集成

- 后端：`mvn verify` 串联 Spotless + Checkstyle + ArchUnit + Enforcer + 单测 + 集成测试；
- 前端：`vp check`（tsgo + Oxlint + Oxfmt）+ `vp test --run`；
- 流水线分层：PR 跑单元/类型/规范；合入 `develop` 跑集成；`release/*` 及发布前跑 E2E + 性能 + 安全；
- 覆盖率门禁：`Jacoco` 报告接入 CI，低于 80% 阻断。
